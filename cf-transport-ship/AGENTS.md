# CF 游戏开发协作

## 先读资料

- 完整产品规格、阶段、规则、画风和验收：[docs/game-design.md](docs/game-design.md)。
- 可手改的装备清单及项目默认参数：[docs/design-data.json](docs/design-data.json)。
- 数量与时长的计算过程：[docs/calculate-design.py](docs/calculate-design.py)。
- 用户的新指令优先于文档。不要把规划中的功能描述成已经实现。

## 项目边界

- 游戏代码、资源、构建和详细设计都在本目录内；沿用 Three.js、原生 JavaScript、esbuild 和单文件 HTML 构建方式。
- 开发顺序为主页与背包、枪械精修与新增副武器、沙漠灰爆破、战术投掷物。每阶段先完成验收再推进下一阶段，用户可调整顺序。
- 团队竞技保留运输船现有的射击、移动、伤害、计分和重生规则；不要用爆破规则覆盖团队模式。
- 爆破地图已确定为 CF 沙漠灰，布局资料等待 Yang 提供；不要用 Dust II 或其他地图替代，不要自行宣称尺寸与路线已经考据。
- 枪械保持现有程序化简化 3D 风格，精修比例、材质和动作。保留原始来源，不引入新的游戏引擎或重型素材流水线。
- 不擅自扩展到真人联机、账号系统、商城、付费武器、皮肤等级或任务成长系统。

## 分工约定

- 开始并行前确定共享数据结构、接口和文件归属。`game.js` 由一个集成 Agent 负责；其他 Agent 通过约定接口交付模块。
- 每阶段保持可启动、可构建，保留别人未提交的改动；不能提交仅加武器数据但缺模型、动画、音效的半成品。
- 修改规划参数后运行计算脚本，同步受影响的设计说明与验收记录。

## 构建与验证

在本目录运行：

```bash
npm ci
npm run build
python3 -m http.server 8000 --bind 127.0.0.1 --directory dist
```

- 验证桌面主菜单、进入对局及退出；手机端自 2026-10-02 起不作为开发与验收项（用户指令），无需为触屏适配或回归，已存在的触屏代码保留现状。
- 核心存储迁移、背包生效和爆破胜负用针对性检查覆盖；视觉修改按实际画面与交互验收。
- 验收证据、实际完成项和限制更新到设计文档的交付记录，不把过程追加到本文件。
- 不提交 `node_modules/`、`dist/`；Git 目标为 Yang 的 fork。
