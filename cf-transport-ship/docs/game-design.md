# 游戏开发规格

## 文档状态与目标

本文件用于交给其他 Agent 分阶段开发，记录已确认的产品方向、项目默认规则与验收标准。M1（主页、背包、运输船）与 M1B（枪械精修、USP / Glock-18）已实现并通过验收，M2、M3 尚未实现；调研基线为提交 `7e8ed6e`。若用户调整范围，以最新指令为准，并同步本文件。

### 用户已确认

- 保留运输船团队竞技及现有整体枪战规则。
- 新增主页，可以选择团队模式或爆破模式，并进入个人界面、背包和武器库。
- 每场可使用三个背包，每个背包含主武器、副武器、近战、投掷物四个槽位。
- 投掷物槽用于选择投掷物，不增加备用主武器或副武器槽。
- 爆破直接使用配置好的背包，采用简化的 CS 爆破目标规则，不加入买枪经济。
- 爆破地图为 **CF 沙漠灰**。不要替换为 CS Dust II、黑色城镇或任意沙色测试地图。
- 枪械沿用当前简化程序化 3D 风格，可以提高精致度，不追求仿真级外观。
- 第一版完成主页、背包与运输船实际使用；新增枪械、沙漠灰爆破、战术投掷物分步加入。
- 最终装备范围为现有主武器、沙漠之鹰、USP、Glock-18、军刀、高爆手雷、闪光弹和烟雾弹。
- **手机端不再是开发与验收要求（2026-10-02 用户指令）**：后续阶段以桌面浏览器为准，不需要为触屏专门适配、验证或回归；已存在的触屏代码保留现状，不作为阶段交付条件。下文 M1B、M2 等段落中涉及手机横屏、触屏交互的条目不再作为验收阻塞项。

### 执行默认值与待补资料

后文的换包时机、短局回合数、交互、界面和新增装备细节，是为落实上述方向选定的项目默认设计，不声称用户逐项指定，也不声称精确复刻原版 CS 或 CF 数值。开发 Agent 可直接据此实现；若更改影响玩法的默认值，应先在任务中说明依据，再同步规格。

沙漠灰的具体参考资料仍待 Yang 提供。精确路线、出生区、掩体、高低差与比例尚未核定。地图还原阶段须先核定参考，不能凭 Dust II 记忆替代。该资料依赖不阻塞主页、背包、武器精修和通用爆破逻辑开发。

装备清单及默认参数集中在 [design-data.json](design-data.json)，每个字段独占一行。它是设计数据，当前游戏不会自动读取它。开发时须将需要的参数接入实际运行模块，并保持一致。

数量与时长由 [calculate-design.py](calculate-design.py) 计算，结果见 [design-summary.json](design-summary.json)。脚本也同步本文的装备表、默认背包示例、爆破参数表与计算段落。现有装备、计划装备的标记表示调研基线状态，不应未经核验改成已交付。

## 产品流程

```text
启动 → 主页
主页 → 团队模式 → 运输船设置 → 选择初始背包 → 对局 → 结算 / 返回主页
主页 → 爆破模式 → 沙漠灰设置 → 选择阵营和初始背包 → 回合对局 → 比赛结算
主页 → 个人界面 → 背包 → 武器库 → 为指定背包的指定槽位装备 → 保存
```

- 主页使用清晰的团队竞技、爆破模式入口，并提供个人界面与设置入口。
- 第一版爆破入口明确显示“开发中”，不进入运输船冒充爆破；完整模式验收通过后开放。
- 个人界面先提供本地昵称、背包与设置。继续使用玩家与机器人对战，本阶段不开发账号登录、服务器或真人联机。
- 设置保留现有灵敏度、FOV、音量、画质和难度。不要在改主页时重新调现有枪械伤害、移动、弹道和后坐参数。
- 新界面采用深色底、清楚的装备卡片和克制的黄色强调，沿用当前游戏气质。中文正文使用一致的系统字体，禁止斜体，留白与按钮点击区域优先。
- 在模式选定前不强制生成运输船及其海面、机器人和导航；可以先显示静态主页，进入对应模式后加载场景。

清单是最终目标。未交付的装备可以在说明页标明计划，但不得出现在可装备列表中；不能配置一个会导致模型或图标初始化失败的 ID。

- 武器库按主武器、副武器、近战、投掷物分类，卡片提供名称、类别、简短用途和统一缩略图。

- 投掷物槽默认选择一种投掷物，每次出生或新回合获得该种投掷物的一枚；本阶段不同时携带高爆、闪光、烟雾。
- 军刀先只提供现有型号，不扩展皮肤或多种近战武器。

### 对局内选择

- 团队竞技按 B 打开背包选择，选择后在下次复活生效。开局使用主页所选背包；阵亡期间也可选下一次复活的背包。
- 第一版不保留原先“出生区即时更换主武器”的特殊入口，统一为下一次复活生效；这是装备系统的明确改动，其他团队规则保留。
- 爆破只在回合准备阶段选择背包，阶段结束后锁定；阵亡期间可以登记下一回合使用的背包，不提前生成装备。
- B 弹窗不是全局暂停，机器人和对局时间继续；打开时阻断并清理移动、开火和视角输入，关闭时不能留下按住的键或鼠标状态。
- `1–4` 切当前背包的四件装备，Q 与滚轮沿用现有切枪操作；背包编号不占这些按键。
- 只有出生或新回合能重新生成弹药和投掷物，选择同一背包、打开页面或切武器都不能刷新补给。
- 换包生效时同步重置开镜、换弹、投掷动作、枪模、持握、HUD 和当前槽位。
- 玩家背包不会覆盖所有机器人的配置。第一版机器人装备沿用现状，后续按模式分配合法装备。

## 枪械美术与新增副武器

### 画风与精致度

视觉基线是当前 `guns.js`、`viewmodel.js` 和 `render.js`。模型继续由基础几何与程序纹理生成，材质保持有层次的简化 3D，而不是扁平无光照风格。

- 先精修侧面轮廓、枪身比例与持握，主要结构一眼可认；不依赖改颜色区分枪型。
- 重点处理枪口、准星、套筒、护木、握把、弹匣底板和接口的比例、少量倒角与连接，避免粗糙方块拼装感。
- 涂层枪身偏哑光，裸钢保留少量高光，木质呈暖棕纹理，聚合物与橡胶偏粗糙。整枪不能全黑一块或全银发亮。
- 微弱磨损、木纹和材质变化使用固定种子的 Canvas 纹理并缓存；不要用大量独立微小网格堆细节。
- 沿用当前独立第一人称武器层、程序手臂、拔枪、后坐、呼吸与行走晃动、检视、换弹、抛壳及狙击拉栓。
- 动作改善以节奏、握持与零件衔接为主，不用大幅摇晃、超亮枪焰或强泛光遮掩模型。
- 每种装备的具体色材与识别结构见装备清单。USP 默认无消音器；Glock-18 默认仅半自动，不开发消音器装卸或连发模式切换。
- 保持现有模型生成与材质系统，不引入扫描贴图、外部高模包、骨骼动画工程或新的引擎。
- 武器库、第一人称和第三人称共享武器 ID 及模型构造。列表用缓存图标，选中后的详细预览才使用单个可复用的 3D 视窗。

### 新手枪的完整性

USP 与 Glock-18 各有独立轮廓、材质和持握配置，均为副武器、半自动。定位为 USP 平稳易控、Glock 容量与近距离节奏、沙漠之鹰高单发伤害；新参数是本项目设计值，开发 Agent 应集中列出参数并试玩调平衡，不套用未知的“原版精确数据”，不改已有武器参数来迁就新枪。

每把新枪必须同时完成：

- `weapons.js` 的完整合法数据及类别信息。
- `guns.js` 独立 builder，以及 `slide`、`mag`、`grip`、`fore`、`muzzle`、`eject`、`magwell` 动作和持握锚点。
- `viewmodel.js` 的位置、后坐、枪焰、套筒与普通/空仓换弹。将仅识别 `deagle` 的手枪分支改为类别或显式能力字段。
- `character.js` 第三人称手枪持握，不把所有新增手枪套用步枪姿势。
- `audio.js` 对应的程序合成音色，不静默回退成步枪音效。
- 武器库、背包、保存迁移、HUD、图标、切枪、击杀提示、死亡与复活完整连通。

`makeIcons()` 当前会遍历所有 `WEAPONS`。不能先注册没有 builder 的武器，再以“后续补模型”交付，因为会影响整个游戏加载。

### 视觉验收

- 各枪在中性侧面预览和第一人称中能凭轮廓区分，深色部分仍有结构层次。
- 静止、开火、换弹、切枪、检视时，手不明显悬空或穿枪；弹匣、套筒与枪栓归位，动作结束没有零件遗失。
- 枪口火焰和抛壳位置正确；动画与弹药、射速、换弹完成时间一致。
- 不靠改运输船世界灯光来掩盖单把枪的问题。
- 枪械在正常视角与检视中不明显裁切（原「手机横屏不遮住准星与关键 HUD」自 2026-10-02 起不再要求）。
- 同设备、画质和尺寸记录修改前后 FPS、draw calls、三角面与纹理数量；反复预览、换枪和开局不能持续增长资源。

## CF 沙漠灰地图

地图目标是可辨认的 CF 沙漠灰，采用与现有游戏一致的简化建筑、程序材质和适量细节；布局还原与画面仿真是不同验收项。

### 参考核定与灰盒

- 由 Yang 提供或认可经典沙漠灰参考。登记版本、来源和参考文件；手机版、新版和竞技改版不能混用。
- 先制作俯视路线图及灰盒，标出双方出生区、A/B 安包区、主要通路、掩体和关键高低差。
- 从图片/PDF 提取的结构化布局先回显给 Yang 确认，再写入坐标或地图配置。缺少可靠尺寸时标为项目比例，不宣称原版精确尺寸。
- 未核定参考前可以做通用 A/B 测试场验证爆破逻辑，但名称必须是测试场，不能把它作为沙漠灰交付。
- 地图数据同时驱动碰撞、雷达和 AI 路线；不要让三者分别维护猜测坐标。
- 玩家与机器人都能从出生区抵达两个包点并转点；必经楼梯、高台、狭口和通路都要实际走通。
- 现有寻路只适用于近地平面，真实高低差需要带高度的导航节点/连接或高度感知寻路。楼梯连接与落差方向必须符合实际通行。

### 美术和性能

- 灰盒通过后再补低饱和沙石墙、石砖地面、木箱、金属门和少量标识。具体物件依参考确定，不凭其他地图记忆补位置。
- 石材、木质、金属材质分层，但避免高密度贴图、遍地装饰和照片式噪声。
- 出生区、路线与安包区域容易辨认，深色服装和枪械不会完全融入阴影。
- 墙体按约定阻挡移动、视线与射击；可穿透的掩体使用明确材质规则。
- 运输船的海面、船速、烟囱、灯光与镜头不能带到沙漠灰。
- 每张地图提供独立场景根节点和资源销毁方法，反复切图没有旧物体、导航、碰撞、灯光、烟雾或计时器残留。

## 简化爆破规则

采用攻守、安包/拆包、单回合死亡等待的核心目标。以下是短局网页游戏的项目默认值，不是原版竞技规则表。

<!-- bomb-defaults:start -->

| 参数 | 项目默认值 |
| --- | --- |
| 对战人数 | 5v5，1 名玩家与 9 个机器人 |
| 比赛结束 | 最多 8 回合，先 5 胜；4:4 平局，无加时 |
| 换边 | 完成第 4 回合后交换攻守 |
| 回合准备 | 8 秒 |
| 未安包阶段 | 90 秒 |
| 安包后炸弹倒计时 | 40 秒 |
| 连续安包交互 | 3 秒 |
| 连续拆包交互 | 5 秒 |
| 回合结算 | 4 秒 |
| 交互距离 | 拆包 2 米，拾取 C4 1.5 米；均须无遮挡 |
| 队友伤害 | 关闭；高爆自伤保留 |
| 拆弹钳 | 无，统一拆包时间 |
| 出生 | 生命 100、护甲 100；准备结束后无保护 |

<!-- bomb-defaults:end -->

- 潜伏者为进攻角色，保卫者为防守角色。比赛中的队伍身份与当前攻守角色分开保存；换边后累计得分和玩家所属队伍不变。
- 准备阶段选择背包，角色不能移动、射击、投掷、安拆包或受到伤害；结束后取消出生保护。
- 每回合重置生命、护甲、弹药与当前背包投掷物。没有经济和普通武器掉落拾取，保留 C4 的掉落与拾取。
- 阵亡后等待下一回合，允许观战存活队友；没有存活队友时只提供固定场景或包点镜头。正常镜头视野内可显示敌人，但不提供敌方跟随视角、敌方标签或雷达位置，也不能自由移动镜头窥探。
- 按 Esc 暂停这个离线对局时，机器人、回合和炸弹计时一并暂停，恢复后以模拟时间继续；准备和结算也遵守同一暂停机制。

### 炸弹与交互

- C4 是独立任务物品，不占四个背包槽；每回合由进攻方一名存活成员携带，死亡掉落，进攻方可拾取。
- 携包者按 5 切到 C4，再按住 E 安包；守方按住 E 拆包。HUD 在符合条件时提示操作和进度。拾取掉落 C4 使用 E 单次操作，不依赖键位 4 的投掷物槽。
- Q 与滚轮仅切四个普通装备槽；从 C4 返回时使用上一个普通装备槽。安包完成后自动返回该槽，没有 C4 时不能进入 C4 手持状态。
- 触屏提供独立的 C4 选择和上下文拾取按钮，安包/拆包使用长按交互按钮及进度提示，松手或触控取消立即中止。按钮不占四槽背包栏，与键盘共享条件、计时和取消规则。（手机端自 2026-10-02 起不再要求，此条仅在日后恢复移动端时适用。）
- 安包要求携带且选中 C4、存活、站稳、处于合法包点且视线没有阻挡。拆包要求防守角色、存活、接近炸弹并无遮挡。
- 交互期间禁止射击、投掷、切枪；移动、松开、离开范围或死亡取消并清零。受伤本身不取消交互。
- 合法交互范围和时间读取设计参数；不要因为武器切换重新计算或绕过耗时。
- 安包完成后停用原回合超时结算，改用炸弹截止时间。
- 交互完成时间必须严格早于对应截止时间；恰好相等时截止事件优先。用模拟时间戳判断，不能由不同设备的帧顺序决定结果。

### 胜负顺序与重置

| 条件 | 结果 |
| --- | --- |
| 未安包，进攻方全灭且仍有防守成员 | 防守方赢回合 |
| 未安包，回合时间到 | 防守方赢回合 |
| 防守方全灭且仍有进攻成员 | 进攻方赢回合 |
| 已安包，进攻方全灭且仍有防守成员 | 回合继续，仍须拆包 |
| 炸弹拆除完成 | 防守方赢回合 |
| 炸弹截止时间到 | 炸弹爆炸，进攻方赢回合 |
| 未安包时双方同时全灭 | 防守方赢回合 |
| 已安包时双方同时全灭 | 进攻方赢回合 |

先按模拟时间排序事件；即使一次更新跨过截止时间，严格早于截止的有效交互仍先处理。恰好同一时间戳时，截止事件优先。非截止的同刻事件先归并全部伤害、死亡与掉包，再验证交互者是否仍存活且满足条件，提交有效安包/拆包，最后统一结算；已拆除优先于存活人数判定。携包者或拆包者在完成同刻死亡时，该次交互无效。双方同时全灭使用该时刻全部伤害后的存活快照，不能在第一条击杀回调中提前结算。

已终结的回合不再接受得分或伤害。实现中集中归并事件并明确上述优先级，不在各个回调里重复调用结算。

每回合只结算一次，比分按赢得回合增加；击杀数仍显示个人数据，不能作为比赛胜分。回合结束清除飞行投掷物、延迟伤害、未完成投掷、安拆进度、声音、旧目标与回合计时器，再进入结算和下一回合。

推荐状态：对局 `准备 / 进行 / 已安包 / 回合结算 / 比赛结束`；C4 `携带 / 掉落 / 已安放 / 已拆除 / 已爆炸`。状态转换通过一个明确入口，不允许地图或 HUD 自行修改胜负。

### 机器人

- 攻方会选择包点、带包、捡回掉落 C4、安包及守包；守方会守点、转点、回防和拆包。
- 不把运输船对称冲锋路线当作沙漠灰策略，地图提供合法任务位置与导航连接。
- 玩家阵亡后机器人也能独立完成目标，而不是始终追敌并耗尽回合。
- 安包、拆包、观察敌人和投掷遵守与玩家相同的范围、耗时和遮挡规则；难度不能通过读取全场敌人实时坐标实现。

## 战术投掷物

高爆手雷保留当前伤害与投掷行为。新增闪光和烟雾均须有模型、手持与投掷动作、碰撞、引爆、消耗、HUD、音效和回合清理。

- 闪光无直接伤害；按距离、观察朝向和实体遮挡计算曝光，影响玩家、队友、敌人和投掷者。
- 默认曝光为距离系数乘朝向系数：距离在满效果范围内为满值，线性衰减到最大范围外为零；朝向系数为 `0.2 + 0.8 * max(0, dot)`，其中 `dot` 是观察者朝向与朝向闪光爆点的单位向量点积，完全被实体挡住为零。
- 玩家白屏/恢复与机器人失去视觉追踪使用同一曝光状态。新闪光取较晚的恢复截止时间，不无限相加。
- 烟雾同时影响画面、机器人视觉与准星姓名提示；不能画面被遮挡而机器人持续精准锁敌。
- 烟雾范围用统一可查询的数据表示，视线穿过有效烟区即遮挡；烟雾不阻挡角色移动或子弹。
- 玩家在烟内有相应视野遮蔽；烟雾使用时长末段淡出，结束后同时移除渲染和视觉遮挡。
- 机器人可根据声音或最后目击位置行动，但不能继续从烟中获取目标实时坐标。
- 本阶段使用常规范围烟雾，不要求 CS2 体积烟、弹孔或爆炸吹散。
- 引爆时间、范围和持续时间见设计数据，是初始试玩参数，不能宣传为原版数值。

## 技术边界与分工

沿用原生 JavaScript、Three.js、esbuild、程序化资源与单文件 HTML；不因新增主页引入 React、路由框架或后端。

建议模块职责如下，具体文件名可由集成 Agent 统一：

| 负责部分 | 职责及交付接口 |
| --- | --- |
| 本地资料与背包 | 加载/验证/迁移/保存 Profile，按 ID 返回合法配装 |
| 主页、个人界面、武器库 | 页面状态与选择，不直接生成弹药或改比分 |
| 地图注册与生命周期 | `modeId`/`mapId` 选择，场景根、出生点、包点、导航、环境和销毁 |
| 模式规则 | 团队与爆破各自处理计分、复活、阶段和结束条件 |
| 炸弹交互 | 携带、掉落、拾取、安拆与截止时间，产出规则事件 |
| 武器与画风 | 完整武器能力、模型、动作、音色和预览 |
| 机器人与可见性 | 地图任务、导航、目标交互、闪光与烟雾遮挡 |
| 集成 Agent | 对局主流程、输入屏蔽、生命周期和整体回归 |

`game.js` 只由一个集成 Agent 修改。并行开发前统一 Profile、Loadout、MapDefinition、ModeRules 与炸弹事件接口，再确定文件归属，避免多个 Agent 同时重写主流程。

调研发现的主要限制：`Actor.giveLoadout()` 固定四件装备；B 只换主武器且出生区换枪会刷新弹药；`Game.init()` 写死运输船和导航边界；`Bot` 路线坐标、出生高度、环境海面与团队复活都需分离。手枪动作/姿势多处只识别 `deagle`，投掷物逻辑也有固定 `he` 和第四槽的假设。

### M1B 修复：结算面板、物理、投掷、存储与枪口（分支 `fix/m1b-issues`，2026-10-02）

实战复现与代码审查发现的 6 个问题，全部修复并补回归检查：

1. **开着背包结束比赛会吃掉结算入口**：`endMatch()` 只切了 HUD 的结算屏，`screens.js` 的背包面板仍盖在最上层。现在结算统一先收起局内面板（`closeBagPanel(true)` + `screens.show(null)` + 收起计分板），`inLoadout` 归位、输入清空。
2. **打开背包会冻结角色物理**：输入屏蔽直接 `return`，跳起时开背包会悬停，而机器人与对局时间继续走。现在屏蔽分支只清操作输入，仍调用 `move(dt, 0, 0, …)` 走重力、碰撞与落地，视角不响应。
3. **复活没清掉上一条命的投掷状态**：投掷蓄力中（`pendingThrow`）阵亡，复活后会在没有输入的情况下把新手雷投出去。`Actor.spawn()` 现在重置 `pendingThrow`、`autoSwitchAt`、`reScope`。
4. **存储异常处理不完整**：`Profile.equip/setNickname/selectBackpack` 现在返回 `{ ok, saved }`，写盘失败时界面提示「已装备到背包N，但无法保存到本地」而不是绿色成功；`normalizeProfile` 在背包 ID 被修复时用原始 ID → 新 ID 的映射，让 `selectedBackpackId` 跟着原来那件背包，不会跳到占据同名 ID 的另一件（配装不再悄悄换人）。
5. **Glock-18 枪焰位置**：`muzzle` 锚点在 z = -0.185，而模型实际枪口在 -0.142，枪焰前伸 4.3 cm。改为 -0.1465，与 USP/deagle 同样保持约 0.45 cm 的枪口余量；九个部件的枪口偏差现在都在 1.5 cm 内。
6. **性能与资源检查口径**：`game.frame` 在 `traceBullet()`/`melee()` 里也会自增，不能当渲染帧数；`tools/capture-guns.mjs` 改为独立 rAF 计数、`info.autoReset = false` 后按帧平均，并新增「反复重新开局」的资源检查。

顺带修掉重新开局检查暴露的资源泄漏：名牌纹理与材质、机器人合并枪械几何体、士兵骨骼贴图（`skeleton.boneTexture`）与材质、`Sky` 自带几何体，此前都只从场景移除而没有 `dispose()`。
